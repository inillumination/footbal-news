# Deployment

## Перед production
- Проверить доступ к VPS и домену.
- Проверить DNS и HTTPS.
- Использовать отдельные сильные пароли.
- SSH по ключам; ограничить доступ.
- Настроить firewall.
- Хранить `.env` вне Git.
- Настроить резервное копирование MariaDB, PostgreSQL и файлов WordPress во внешнее защищённое хранилище.
- Проверить восстановление из резервной копии.
- Настроить health checks и уведомления.
- Не выполнять миграции на production без backup.

## Состав резервных копий
- Включать базу MariaDB WordPress и базу PostgreSQL, используемую News Engine и Football Data Engine.
- Включать загруженные медиафайлы и другие файлы, необходимые для восстановления сайта.
- Секреты не хранить в Git; если они нужны для восстановления, хранить отдельно в защищённом хранилище с ограниченным доступом.
- Очереди Redis/Celery считать восстанавливаемыми задачами, а не источником истины; резервировать их только если там появится постоянное бизнес-состояние.
- Периодически проверять восстановление в изолированной среде, не на production.

## День 2
Проверка VPS, домена, DNS, HTTPS и Git выполняется без изменения их настроек.
Любые изменения DNS, firewall, SSH, конфигурации VPS, production или секретов требуют отдельного подтверждения пользователя.

## Не выполнять автоматически
Codex не должен менять DNS, firewall, SSH, production secrets или удалять данные без отдельного подтверждения пользователя.
