# Architecture

## Компоненты
1. WordPress — CMS и публичный сайт.
2. Тема `football-media` — только представление.
3. Плагин `football-media-core` — таксономии, метаданные, REST-интеграции и WordPress-специфичная логика.
4. Python News Engine — сбор и редакционная подготовка новостей.
5. Football Data Engine — получение футбольных данных от провайдера.
6. MariaDB — данные WordPress.
7. PostgreSQL — данные Python-сервисов.
8. Redis/Celery — фоновые задания.

## Владение данными и синхронизация
- WordPress является источником истины для отредактированных и опубликованных статей. PostgreSQL News Engine хранит источники, исходные записи, этапы обработки и аудит; таблица опубликованных материалов связывает устойчивый article_uuid с WordPress post ID.
- PostgreSQL Football Data является источником истины для нормализованных записей провайдера.
- Плагин football-media-core хранит только нужную сайту проекцию футбольных данных с идентификаторами провайдера и временем обновления. Поля провайдера следует отделять от редакционных полей WordPress.
- Поток футбольных данных: провайдер -> Python-сервис -> PostgreSQL -> защищённая REST-синхронизация через плагин -> локальные данные WordPress. Тема читает данные WordPress; прямых запросов к провайдеру при просмотре страниц нет.

## Поток новостей
Разрешённый источник -> загрузка -> нормализация -> дедупликация -> извлечение фактов -> проверка -> AI-черновик -> контроль качества -> WordPress.

## Поток матчевых данных
Поставщик API -> плановая синхронизация -> проверка и нормализация -> база/кэш -> WordPress.

## Принципы
- Секреты только в окружении.
- Внешние API вызываются сервером, не браузером.
- На страницах не должно быть прямого запроса к провайдеру при каждом просмотре.
- Компоненты должны иметь health checks и понятные логи.
