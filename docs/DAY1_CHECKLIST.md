# День 1 — чек-лист

## Цель
Подготовить проектную документацию и безопасную структуру репозитория.

## Задачи
- [ ] Открыть папку проекта в Codex.
- [ ] Добавить стартовые файлы из архива.
- [ ] Прочитать README и AGENTS.
- [ ] Передать Codex задание первого дня.
- [ ] Проверить созданные документы.
- [ ] Убедиться, что `.env` не попадает в Git.
- [ ] Создать первый Git commit.

## Критерии приёмки
- [ ] В корне есть README, AGENTS, .gitignore, .env.example.
- [ ] В docs есть документы MVP.
- [ ] Codex не создавал ненужный production-код.
- [ ] В документах нет реальных секретов.
- [ ] Есть список открытых вопросов и рисков.
- [ ] Первый commit создан.

## Отчёт в конце дня
1. Что сделано?
2. Какие файлы созданы/изменены?
3. Какие проверки выполнены?
4. Какие вопросы остались?
5. Готов ли проект к дню 2?

## Ограничения Дня 1
- Не писать функциональный код сайта.
- Не устанавливать WordPress, Docker, базы данных и внешние сервисы.
- Не выполнять запросы к внешнему API и не менять инфраструктуру.

## Открытые решения перед реализацией
- Проверить покрытие выбранных турниров и сезонов у провайдера на фактических ответах.
- Утвердить категории и источники, для которых когда-либо будет разрешена автопубликация.
- До публикационного кода определить права сервисной учётной записи WordPress и уточнить журналирование REST-доставки.
- На Дне 2 выполнять только read-only инвентаризацию; изменения инфраструктуры согласовывать отдельно.
