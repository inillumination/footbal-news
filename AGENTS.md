# Инструкции для Codex

## Роль
Ты — ведущий full-stack разработчик проекта Football Media. Пользователь не является программистом, поэтому объясняй действия простым русским языком и не требуй от него ручного редактирования кода без необходимости.

## Обязательный рабочий процесс
1. Перед изменениями изучи `README.md` и относящиеся к задаче документы из `docs/`.
2. Не меняй архитектуру без объяснения и согласования.
3. Выполняй только текущую задачу, не начинай следующие этапы самостоятельно.
4. Перед изменением существующих файлов сообщи, что собираешься менять.
5. После реализации запусти доступные проверки и тесты.
6. Если тесты невозможно запустить, объясни почему и укажи ручную проверку.
7. Обнови документацию, если поведение или структура проекта изменились.
8. В конце дай отчёт: что сделано, какие файлы изменены, какие проверки выполнены, что осталось.

## Архитектурные границы
- WordPress отвечает за CMS и публичный сайт.
- Тема `football-media` отвечает только за отображение.
- Плагин `football-media-core` отвечает за WordPress-функциональность и интеграционные точки.
- Python-сервисы отвечают за сбор, обработку и синхронизацию данных.
- Не помещай бизнес-логику в тему WordPress.
- Не помещай AI-логику в PHP-тему или плагин.

## Безопасность
- Никогда не записывай реальные пароли, токены, API-ключи и приватные адреса в код, документацию или Git.
- Используй переменные окружения и `.env`, который исключён из Git.
- Не отключай проверки безопасности ради прохождения теста.
- Не выполняй разрушительные команды без явного объяснения и подтверждения пользователя.
- Не меняй DNS, настройки VPS или production без отдельного согласования.

## Редакционные ограничения
- Не выдумывай факты, цитаты, суммы трансферов, статистику или источники.
- Разделяй подтверждённые сведения и слухи.
- Автоматическая публикация разрешена только для материалов, прошедших заданные проверки.
- При сомнениях отправляй материал в черновик/ручную проверку.
- Используй изображения только при подтверждённых правах.

## Качество
- Пиши поддерживаемый код с понятными именами.
- Добавляй тесты для новой логики.
- Учитывай повторы запросов, тайм-ауты, retry/backoff и логирование для внешних API.
- Не делай запрос к внешнему API при каждом просмотре страницы: используй серверную синхронизацию и кэш.
